# 私有文档记忆合同

## 边界

私有文档记忆位于 Skill 根目录的 `.local/`，整个目录由 Git 忽略，也不得进入发布归档或公共示例：

- `.local/index.json`：版本化档案索引。
- `.local/trusted.json`：版本化、按文档和操作收窄的用户授权记录。
- `.local/documents/`：每个文档的非敏感写作和结构约定。
- `.local/archive/`：迁移或替换前的可恢复原件与清单。

公共 Skill 不预置任何真实文档档案或信任标识。日志写入、档案维护和信任维护是三个独立动作。

## 索引结构

索引顶层结构固定为 `{version: 1, profiles: [...]}`：只用 `version` 表示 schema 版本，并用 `profiles` 保存非空档案数组。不得使用旧的文档数组键替代 `profiles`。每个 profile 至少包含以下精确键：

- 身份与文件：`profile_id`、`aliases`、`memory_path`；
- 实时目标：`canonical_url`、`document_token`、`wiki_node_token`；
- 分类上下文：`document_kind`、`log_types`、`audience`、`language`、`timezone`；
- 结构策略：`date_semantics`、`ordering`、`stable_headings`、`insertion_rules`、`protected_regions`；
- 治理字段：`sensitivity`、`visual_policy`、`correction_policy`、`migrated_at`、`last_verified_at`。

Docx profile 不使用 Wiki 节点字段；Wiki-backed Docx profile 同时记录规范 Wiki 节点和实时解析出的底层文档目标。`migrated_at` 必须是带显式时区的 ISO 8601 时间。未完成实时核验时，`last_verified_at` 保持空值，不用迁移时间冒充核验时间。

标识只存在于忽略目录的索引中。活动记忆文件保存结构、受众和写作约定，不重复保存目标标识。

## 信任标识

`.local/trusted.json` 顶层固定为 `{version: 1, grants: [...]}`。每个 grant 必须且只能包含：

- `profile_id`：引用索引中的唯一 profile；
- `target_fingerprint`：由 `profile_id`、规范 URL、文档类型和规范目标 token 计算的 `sha256:` 摘要；Wiki 同时绑定节点 token 与底层 `document_token`，任一目标变化即失效；
- `identity`：固定为 `user`；
- `operations`：只允许 `append`、`block_insert_after`；
- `log_types`、`audiences`：不得超出对应 profile；
- `authorized_at`、`expires_at`、`revoked_at`：带显式时区的 ISO 8601；后两者可为 `null`。

使用 `scripts/private_memory.py trust-fingerprint` 为实时精确目标生成摘要。复用 Wiki 信任时必须先实时解析节点，并向 `trust-fingerprint` 和 `resolve` 传入 `--backing-document-token`；缺少或不匹配时不能依据该记录写入。信任文件存在时，`validate` 和 `resolve` 会自动校验它；未知字段、重复 profile、目标漂移、破坏性操作、身份或内容范围扩大都使该持久信任路径无效。

信任标识不创建写入意图。复用持久信任时，`resolve` 同时接收 `--explicit-write-intent`、精确 URL/token、Wiki 实时底层 Docx token（如适用）、`--write-operation`、`--log-type`、`--audience` 和 `--identity user`；操作参数必须与最终执行动作相同，不能把文末 `append` 的结果用于锚点后 `block_insert_after`。返回 `may_mutate=true` 与 `trust_status=trusted` 表示本次请求满足该 grant。明确写入意图可以来自同一会话中仍有效的用户要求，不局限于最近一条消息。

解析器只检查持久信任，不解释会话授权。`may_mutate=false` 或档案读取错误不能单独判定所有写入都未授权。用户已明确授权实时目标与普通追加范围时，可在没有 profile 或有效 grant 的情况下继续，不创建或修改 `.local/`。缺失、过期或撤销的 grant 不支持历史授权复用；目标漂移或范围变化仍须澄清，不能把旧授权套用到新目标。完整执行条件见执行与安全参考。

## 禁止内容

不得保存凭据、Cookie、密钥、认证状态或登录状态、个人信息、块 ID、revision、owner ID 或原始 API 返回。信任文件保存的是用户对特定目标和操作的授权决定，不得写入 OAuth 状态、权限令牌或认证材料。

档案只表达相对稳定的约定，不保存一次写入的临时定位信息。日志正文需要的个人信息仍按最小化原则处理，不能因为档案位于忽略目录就放宽隐私要求。

## 匹配顺序

1. 接受用户本次明确给出的 URL 或标识作为首要线索。
2. 从实时服务解析规范文档类型、节点关系和底层文档目标。
3. 用实时规范标识精确匹配一个私有 profile。
4. 唯一别名只能形成候选；完成实时核验后才允许写入。

多个候选时停止并要求用户选择。没有档案时继续使用实时文档，不自动创建 profile，也不从相似名称猜测。跨受众、跨客户或跨环境的档案不得相互回退。

实时远端内容决定实际结构和位置；档案标题或顺序过时时按实时结构定位，不据旧记忆写入。保护区域发生冲突时先核实，不自动解除保护。写作风格则按当前要求、适用的已确认约定和代表性内容判断；单条异常或助手生成的记录不自动覆盖已确认偏好。

## 文档风格的沉淀

沿用现有 `memory_path` 指向的 Markdown 笔记，无需新增索引字段或风格引擎。笔记可记录标题、日期显示格式、篇幅、术语密度、口吻、段落与表格习惯、视觉说明方式，以及适用章节、受众和日志类型。只保存理解规则所需的非敏感摘要或短例，不复制整份日志、客户细节或操作回执。

区分已确认约定与暂定观察，写明依据类型、适用范围、确认或观察时间。明确的长期要求或用户纠正可以确认约定；有代表性的重复写法支持暂定观察。助手输出、用户沉默、孤立导入和一次性例外不能被记作用户确认。新纠正替换对应旧约定并简记修订原因，避免累积互相冲突的要求。

下面是虚构的自由格式笔记示例，不是必填字段或新的 JSON 合同：

```markdown
# 运营更新章节的写法

适用：运营读者的发布说明章节，不适用于工程附录。
已确认：加粗日期起行；通常一段说明变化，必要限制留在正文。
依据：用户在 2026-09-01 明确要求今后沿用这种写法。
暂定观察：近期人工维护条目使用“可用范围”；尚未确认是固定术语。
短例（虚构）：**9 月 1 日** 试用区域已开放筛选功能，其他区域暂未开放。
例外：本次事故复盘采用长时间线，仅适用于该记录。
修订：2026-09-03 按用户纠正取消“每条必须两句话”，保留必要限制。
风格维护许可：用户允许持续维护本章节的非敏感写作约定，当前有效；
不包含其他章节、信任记录或云端写入。依据为同日明确维护要求。
```

持续维护许可必须源于用户针对该文档的明确要求，记录范围、依据、有效状态及适用的到期或撤销条件。已有许可仍有效且范围未变时，可维护相应笔记而无需每次询问；用户要求停止、许可到期或目标漂移后停止积累或修订风格。明确的停止请求包含将既有许可标记为已停止的最小更新，记录停止依据以免后续会话误用旧许可；这不授权继续学习。若用户同时禁止任何本地文件改动，则遵循该限制并说明旧许可尚未落盘撤销。已确认风格仍可在适用且未被撤回时辅助本次写作，但不能据此恢复维护权限。

风格维护许可不放入 `trusted.json`，不产生 grant、写入意图或远端权限，也不允许自动改动索引目标与保护策略。用户明确要求记住但尚无档案时，先核对目标，再按现有 v1 合同建立所需档案；不能为了普通追加强制建立档案。每次档案维护后运行 `private_memory.py validate`，但它只验证数据合同和隐私，不验证自然语言许可是否成立。没有维护许可时只在本次任务中使用观察，不落盘；本技能升级不替现有文档开启持续维护。

## 变更与归档

修改 `.local/` 需要用户当前明确要求“记住”“更新文档档案”“信任该文档”“撤销信任”等，或既有文档范围内仍有效的持续风格维护许可。后者只支持约定范围内的非敏感笔记维护；普通追加、回填或更正本身不授予档案或信任维护权限。信任标识的创建、修改或撤销仍需相应明确要求。

迁移前先把原件复制到 `.local/archive/`，记录文件名、大小、摘要和迁移时间，再从头生成清理后的活动记忆。归档原件不得发布。升级公共 Skill 时先备份安装目录中的 `.local/`，替换公共文件后原样恢复；既有安装档案优先，不隐式合并来源档案。
