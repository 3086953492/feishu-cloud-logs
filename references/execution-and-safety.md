# 执行与安全

## 运行时选择

采用能力检测，不以版本号建立永久白名单。先使用本地已安装运行时，读取其当前版本匹配的 `lark-shared`、`lark-doc`、`lark-wiki` 及所需参考，并探测 `skills.read`、Docx 创建／读取／更新、Wiki 解析和风险确认能力。

版本 1.0.72 只是当前验证证据，也是 `compatibility.json` 中的固定回退版本，不是版本上限。不得使用 mutable、latest 或其他未固定回退。本地运行时不可用时，只有在用户确认后才使用固定 npx 回退。探测脚本只检查版本和能力，不安装、不认证、不访问真实文档。

## 身份与权限

默认使用用户身份，不自动切换机器人。权限不足时说明缺失动作，只请求当前操作所需的最小权限。不得把认证状态、凭据或响应原文写入日志或私有档案。

## 写前解析

创建前检查目标父级中是否已有同名文档。父级 token 与父级 position 互斥，只传一种。先解析 Wiki 节点与底层 Docx，再确认规范目标和写入位置。

读取完成任务所需的最小范围。只有精确块操作才临时获取块 ID，操作结束后丢弃。写入前记录当前 revision、稳定标题、逻辑锚点、预期相邻内容和正文摘要。

## 并发与幂等

使用当前 revision 做乐观并发控制。revision 冲突后重新读取最小范围，重新定位逻辑锚点并重新生成补丁；不得移除并发修改或用旧块 ID 重试。

创建和追加都不是天然幂等操作。执行前检查同名目标、稳定标题、逻辑锚点和预期正文。超时后重复相同检查，确认未写入后才能重新执行。不得用重复命令赌第一次失败。

## 结果未知

进程超时、响应缺失、warning 非空、`partial_success`、媒体上传状态不明或返回无法解析时，将状态标记为“结果未知”。先读回规范目标并核对位置、锚点和预期内容，不盲目重试，也不把未知报告为失败或成功。

媒体上传不明时同时检查正文引用和媒体可访问状态。读回发现正文已经存在时停止重试；正文部分存在时展示差异并请求用户决定修复方式。

## 破坏性操作

仅满足下述“受信普通追加”条件时不重复确认；否则保持既有确认流程。用户只要求草稿时禁止云端写入。

### 受信普通追加

仅当以下条件全部满足时跳过二次询问：

1. 用户本轮明确要求写入，而不是只要求草稿、审阅或规划；
2. 实时规范 URL 与目标 token 精确匹配私有 profile；Wiki 目标还须把实时解析出的底层 Docx token 作为 `--backing-document-token` 传入并精确匹配；
3. `scripts/private_memory.py resolve` 对本次 `user` 身份、日志类型、受众和 `append`／`block_insert_after` 返回 `may_mutate=true`、`trust_status=trusted`；
4. 草稿仍通过隐私检查，写入位置仍通过 revision、稳定锚点和保护区域检查。

当前请求中的明确写入要求已经构成普通追加意图，不再询问“是否确认写入”。信任标识缺失、无效、过期、已撤销或范围不匹配时，不得自行补写标识或扩大历史授权。

删除、覆盖、批量重排和历史恢复前，必须展示：

1. 规范目标和精确位置；
2. 受影响标题、块或时间范围；
3. 写前与写后的差异预览；
4. 可恢复方式和不能自动恢复的风险。

取得用户确认后再执行；目标或影响范围变化时重新确认。事故、审计和决策历史使用追加式更正，不以破坏性操作隐藏旧记录。

## 完整成功判定

只有以下条件全部满足才报告成功：进程退出成功、`ok=true`、业务结果为 `success`、warning 为空、规范目标与位置正确，以及写后读回正文与预期内容等价。

任何一项不满足，都报告已确认的状态、未确认部分和下一项安全核验动作。日志内容仍必须遵守密钥禁入和个人信息最小化规则。
