# 八类日志写作示例

以下内容全部虚构，用来展示不同组织方式，不可直接当作真实事实发布。它们是完整记录的参考，不是必填字段表；日期、篇幅、术语和版式依当前文档而定。独立记录用默认 `--profile full`，章节内片段用 `--profile append`。只有希望核对字段式模板时才启用 `--check-template`，不应为消除建议而补造内容。

## 简短追加

已知待发布章节的上下文与验证依据时，可以只补一段：

```markdown
操作菜单展开后被遮挡的问题已修复，并通过对应场景验证；正式发布时间待确认。
```

片段可沿用已读取的受众、日期口径和层级，不重复完整元数据。若章节表示正式发布日期，未发布内容应放入待发布区域，不能把提交或记录时间冒充发布时间。

<a id="release"></a>

## 发布／产品变更日志 (release)

适合以短段落向操作人员说明变化的文档；有更多必要限制时自然展开。

```markdown
**2026 年 9 月 1 日 · 列表筛选已开放**

已向试用区域开放按处理状态筛选列表的功能，操作人员可更快找到待处理项目，无需额外设置。其他区域尚未开放，已有保存条件继续有效。
```

<a id="engineering"></a>

## 工程变更日志 (engineering)

适合保留实现依据和可复核验证的工程记录，不要求删除读者需要的术语。

```markdown
# 缓存更新顺序调整，尚未部署

写入主数据后再失效缓存，避免旧值在提交前被重新填入。此次仅修改更新链路，不涉及数据迁移或外部依赖变更。

并发测试中，提交后的读取均返回新值；失效失败的重试路径通过故障注入验证。尚未进行跨区域压测，当前结论不覆盖该环境。

部署后若缓存失效错误持续上升，应回滚此次链路变更，并核对受影响数据的缓存状态。
```

<a id="project"></a>

## 项目／进展日志 (project)

适合按周期汇总的项目章节；可以沿用已有状态标记和列表密度。

```markdown
## 9 月第一周：试点范围保持不变

- 已完成试点流程联调，验收材料已提交，尚未获得上线批准。
- 外部接口联调仍受测试环境排期影响，可能推迟下一轮验收。
- 本周会议决定先完成内部场景验收，扩大试点的决定暂缓。
- 下一步是收齐验收反馈并确认接口联调窗口；扩大范围的时间尚未确定。
```

<a id="incident"></a>

## 事故／运维日志 (incident)

适合时间线。时间依据应可核验，根因与恢复状态分别表达。

```markdown
# 9 月 2 日列表读取延迟：已恢复，根因待确认

内部定级为二级；受影响的是试用区域的列表读取，写入链路未见异常。以下时间均为当天北京时间，来自监控和响应记录。

| 时间 | 观察或行动 |
| --- | --- |
| 10:05 | 列表读取延迟告警触发。 |
| 10:12 | 暂停后台批量刷新，延迟开始下降。 |
| 10:20 | 连续观察窗口内延迟恢复到日常水平。 |

恢复效果已由监控验证；后台刷新与本次延迟相关，但尚不能确认因果关系。后续需要复现并检查资源竞争，已有时间线保留，更正另行追加。
```

<a id="decision"></a>

## 决策日志 (decision)

适合解释取舍的连续叙述，理由无需拆成许多空栏目。

```markdown
# 暂时保留人工复核

9 月 3 日的项目评审决定，试点阶段继续由人工复核异常记录。评审比较了完全自动放行与人工复核两种方式：前者减少等待，但当前异常样本不足以证明误放风险可接受。

这一选择增加处理耗时，也限制试点规模。待异常类型覆盖充分且误放风险得到验证后重新评审；本次决定不推及正式全面运行阶段。
```

<a id="experiment"></a>

## 实验／研究日志 (experiment)

适合保留方法与讨论的较长记录，不能为了短句风格压掉不确定性。

```markdown
# 分组导航能否缩短查找时间

本轮试验比较原始列表与分组导航。在 24 名内部志愿者中交叉安排两种界面，每人完成同一组查找任务；指标为任务开始到正确选择目标的时间。两种界面的先后顺序交替安排，以降低顺序影响。

观察到分组界面的中位耗时低于原始列表，但差异主要出现在熟悉业务的参与者中。此次试验没有覆盖首次接触业务的外部用户，样本也来自内部自愿报名，因此不能据此推断所有用户都将受益。

下一轮将加入新用户并检查错误选择率，避免把更快但更易出错的操作解释为体验改善。在此之前，仅将结果视为继续研究的依据，不作推广结论。
```

<a id="audit"></a>

## 审计／合规日志 (audit)

适合逐项对照证据与整改进度。表格宽度服从真实比较需要。

```markdown
# 第三季度访问复核抽样

本轮检查覆盖内部试点的访问申请和撤销记录，证据来自审批归档与权限清单；未抽样部分不在结论范围内。

| 检查项 | 发现与依据 | 影响 | 整改进度 |
| --- | --- | --- | --- |
| 撤销及时性 | 抽样中有两项超过内部规定时限 | 存在访问窗口延长风险 | 已撤销，流程调整待复核 |
| 申请留痕 | 抽样均可关联审批记录 | 本样本未见缺口 | 无新增整改 |

后续复核将检查流程调整是否持续有效，本次记录保留，发现变化另行更正。
```

<a id="support"></a>

## 客户反馈／支持处理日志 (support)

适合简明的处理闭环；客户标识只保留必要且获准的内容。

```markdown
**导出文件无法打开的问题已恢复**

反馈中提到部分导出文件缺少内容。支持团队依据脱敏复现材料定位了生成中断问题，修复后重新生成的样本已通过打开与内容核对。已通知受影响用户重新导出；历史文件不会自动修复，后续将继续核对是否存在同类反馈。
```
